# NForce Pulse — Technology Stack

> **NForce Pulse** is a role-based Time Tracking System with approval workflows, dashboards, reports, and notifications — built for Admin, Manager, and Employee roles.

---

## 3. Database Stack

| Technology | Version | Purpose |
|---|---|---|
| **MySQL** | (Railway managed) | Relational database |
| **Sequelize ORM** | 6.37.8 | Object-relational mapping |

### Entity Relationship Summary

| Model | Table | Primary Key | Foreign Keys | Relationships |
|---|---|---|---|---|
| **User** | `users` | `id` | `managerId` → User | Self-referencing (Manager ↔ Subordinates); hasMany Projects, TimeEntries, Timesheets, Notifications, AuditLogs |
| **Client** | `clients` | `id` | — | hasMany Projects, TimeEntries |
| **Project** | `projects` | `id` | `clientId` → Client, `managerId` → User | belongsTo Client/User; hasMany Tasks, TimeEntries; belongsToMany Users (via ProjectUser) |
| **Task** | `tasks` | `id` | `projectId` → Project, `assignedTo` → User | belongsTo Project; hasMany TimeEntries |
| **TimeEntry** | `time_entries` | `id` | `userId` → User, `managerId` → User, `clientId` → Client, `projectId` → Project, `taskId` → Task | Unique index on (userId, entryDate, projectId) |
| **Timer** | `timers` | `id` | `userId` → User, `clientId` → Client, `projectId` → Project, `taskId` → Task | Live tracking with pause/resume |
| **Timesheet** | `timesheets` | `id` | `userId` → User | Unique index on (userId, weekStartDate); status: DRAFT/SUBMITTED/APPROVED/REJECTED/PARTIALLY_APPROVED |
| **ApprovalHistory** | `approval_history` | `id` | `actorId` → User, `timeEntryId` → TimeEntry, `timesheetId` → Timesheet | Audit trail for submit/approve/reject/withdraw/comment actions |
| **Notification** | `notifications` | `id` | `userId` → User | Types: MISSING_ENTRY, PENDING_SUBMISSION, SUBMITTED, APPROVED, REJECTED, MANAGER_REMINDER |
| **AuditLog** | `audit_logs` | `id` | `userId` → User | Generic audit with action, entity, entityId, details, ipAddress |
| **BillingRate** | `billing_rates` | `id` | `userId` → User, `projectId` → Project | Billing/cost rates with effective date ranges |
| **ProjectUser** | `project_users` | `id` | `projectId` → Project, `userId` → User | Junction table; unique index on (projectId, userId) |
| **Holiday** | `holidays` | `id` | — | Static holiday dates auto-seeded; used by `classifyEntry()` |

### Key Relationships

- **One-to-Many**: User → TimeEntries, User → Timesheets, Client → Projects, Project → Tasks
- **Many-to-Many**: User ↔ Project (through ProjectUser)
- **Self-referencing**: User → User (managerId for Manager ↔ Subordinates)
- **Composite Unique Indexes**: `(userId, entryDate, projectId)` on time_entries, `(userId, weekStartDate)` on timesheets, `(projectId, userId)` on project_users

## 4. Deployment Stack

| Component | Platform | Details |
|---|---|---|
| **Frontend** | Vercel | Deployed via Vite build; env var `VITE_API_URL` |
| **Backend** | Railway | Node.js Express with Nixpacks; `npm start` entry point |
| **Database** | Railway MySQL | Auto-provisioned MySQL with SSL connection; connection pooling (max 2) |
| **Source Control** | GitHub | Repository: `github.com/RSaishashank/nforce-timetracker` |

### Environment Variables

| Variable | Used In | Purpose |
|---|---|---|
| `PORT` | Backend | Server port |
| `JWT_SECRET` | Backend | Token signing |
| `CORS_ORIGINS` | Backend | Comma-separated allowed CORS origins |
| `VITE_API_URL` | Frontend | Backend API base URL |
| `MYSQL_URL` / `MYSQL_PUBLIC_URL` | Backend | Database connection string |
| `MYSQLHOST` / `MYSQLUSER` / `MYSQLPASSWORD` / `MYSQLDATABASE` / `MYSQLPORT` | Backend | Fallback DB connection |
| `DB_SSL` | Backend | MySQL SSL toggle |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` | Backend | Nodemailer email config |
